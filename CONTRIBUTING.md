# Contributing

Thank you for helping build a small, practical ML reproducibility aid.

1. Search existing issues, then file a new issue with a sanitized manifest and expected behavior.
2. Create a branch and add focused tests (`python -m unittest discover -s tests -v`).
3. Keep the core read-only and standard-library-only unless there is a compelling benefit.
4. Submit a pull request describing the problem, example invocation, behavior change, tests, and any limitations.

Security and privacy: never include private checkpoints, datasets, tokens, proprietary project code, or secrets in issues or PRs. Use synthetic reproducible examples. The project does not promise formal security review; responsible reports can be sent privately via GitHub's security advisory flow once the repository is live.

Project governance: maintainers will make decisions publicly via issues/PR reviews and will document releases, changes, and unresolved problems. Please be respectful and constructive.
